# 单体架构，MySQL 为唯一事实源，Redis 仅作加速

需要一个能扛住热点场次并发抢票的票务平台，但只有个人维护。决定采用单个 Spring Boot 进程、单个 MySQL、单个 Redis：库存与订单的最终正确性完全由 MySQL 的唯一约束和条件更新保证，Redis 只承担选座锁、库存预扣和等待室准入，丢失后可从数据库重建。

**考虑过的方案**：按领域拆微服务（库存、订单、支付各一个服务）。被否决——分布式事务、跨服务一致性和运维成本远超收益，且单机 Redis 与数据库约束已足以防超卖。

**后果**：所有并发正确性测试必须围绕数据库约束编写；任何新增缓存都必须设计成可重建，不能成为事实源。
